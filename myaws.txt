Theory:

Incident Response Phases

-   Phase 1: Detection

-   An automated alert flagged unauthenticated public downloads of sensitive data from IP 117.216.43.193.

-   Phase 2: Analysis

-   CloudTrail Event history confirmed the root user executed PutBucketPolicy on bucket s3-issue-123, applying a wildcard policy that allowed public read access.

-   Phase 3: Containment

-   Immediately enabled S3 Block Public Access on the bucket to halt active data leakage.

-   Phase 4: Eradication

-   Deleted the insecure bucket policy statement granting public s3:GetObject permissions.

-   Phase 5: Recovery

-   Confirmed public requests return AccessDenied while authorized access works. Checked S3 Versioning to verify data integrity and roll back any altered objects.

-   Phase 6: Lessons Learned

-   Enforce Block Public Access at the account level, restrict root account usage via IAM least privilege, enable S3 Versioning, and configure CloudWatch alarms for policy updates.
